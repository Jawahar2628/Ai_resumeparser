# Technical Candidate Resume Analysis Attributes

## 1. Candidate Profile

Analyze the candidate's overall professional profile:

-   Total professional experience
-   Relevant experience for the target role
-   Current/most recent job title
-   Seniority level
-   Primary technical domain
-   Primary specialization
-   Industry/domain experience
-   Current location, if relevant to the role
-   Education and certifications

------------------------------------------------------------------------

## 2. Technical Skills

Extract and categorize all technical skills.

### Programming Languages

Examples: - Java - Python - JavaScript - TypeScript - C# - C++ - Go -
Rust

### Frameworks and Libraries

Examples: - React - Angular - Vue - Node.js - Spring Boot - .NET -
Django - FastAPI

### Databases

Examples: - PostgreSQL - MySQL - MongoDB - Redis - Elasticsearch

### Cloud Platforms

Examples: - AWS - Azure - Google Cloud

### DevOps and Infrastructure

Examples: - Docker - Kubernetes - Terraform - Jenkins - GitHub Actions -
CI/CD

### Other Technical Areas

Examples: - REST APIs - GraphQL - Microservices - Event-driven
architecture - Machine Learning - Generative AI - Cybersecurity -
Testing and automation

------------------------------------------------------------------------

## 3. Skill Proficiency

Do not assume proficiency simply because a skill appears in the resume.

For each important skill, analyze:

-   Skill name
-   Evidence of usage
-   Number of years used
-   Most recent usage
-   Frequency of usage
-   Production experience
-   Project complexity
-   Level of responsibility
-   Estimated proficiency

### Suggested proficiency levels

  -----------------------------------------------------------------------
  Level                               Description
  ----------------------------------- -----------------------------------
  Beginner                            Limited exposure or basic usage

  Intermediate                        Used independently in projects

  Advanced                            Strong production experience and
                                      problem solving

  Expert                              Deep expertise, architecture
                                      decisions, mentoring, or technical
                                      leadership
  -----------------------------------------------------------------------

------------------------------------------------------------------------

## 4. Experience Analysis

For each employment position, extract:

-   Company
-   Job title
-   Start date
-   End date
-   Duration
-   Responsibilities
-   Technologies used
-   Projects worked on
-   Team size, if available
-   Leadership responsibilities
-   Business domain
-   Major achievements
-   Measurable outcomes

------------------------------------------------------------------------

## 5. Project Experience

Analyze projects based on technical complexity and candidate ownership.

Important attributes:

-   Project name
-   Project description
-   Candidate's role
-   Technologies used
-   Architecture
-   Scale
-   Number of users/transactions, if available
-   Integrations
-   Performance requirements
-   Security requirements
-   Deployment environment
-   Candidate ownership
-   Business impact

### Strong evidence

Prefer statements such as:

-   "Designed and implemented..."
-   "Led the migration..."
-   "Built and deployed..."
-   "Reduced latency by 40%..."
-   "Improved system reliability..."
-   "Handled 1M+ requests per day..."

over generic statements such as:

-   "Worked on..."
-   "Involved in..."
-   "Knowledge of..."
-   "Familiar with..."

------------------------------------------------------------------------

## 6. Architecture and System Design

For experienced technical candidates, analyze evidence of
architecture-level skills.

Look for:

-   Monolithic architecture
-   Microservices
-   Distributed systems
-   Event-driven architecture
-   Serverless
-   REST
-   GraphQL
-   Message queues
-   Caching
-   Load balancing
-   High availability
-   Fault tolerance
-   Scalability
-   Database design
-   API design
-   Security architecture

Determine whether the candidate:

-   Used the architecture
-   Designed the architecture
-   Implemented the architecture
-   Made architecture decisions
-   Led architecture changes

------------------------------------------------------------------------

## 7. Problem-Solving Ability

Look for evidence that the candidate solved technically difficult
problems.

Examples:

-   Performance optimization
-   Memory optimization
-   Scalability issues
-   Production incidents
-   Database optimization
-   API performance
-   Migration challenges
-   Reliability improvements
-   Security vulnerabilities
-   Complex integrations
-   Legacy system modernization

Strong resumes should ideally describe:

**Problem → Action → Result**

Example:

> API response times were reduced from 2 seconds to 500 ms by optimizing
> database queries and introducing caching.

------------------------------------------------------------------------

## 8. Achievements and Impact

Identify measurable achievements.

Look for metrics such as:

-   Percentage improvement
-   Cost reduction
-   Revenue impact
-   Performance improvement
-   Number of users
-   Number of transactions
-   Availability/uptime
-   Deployment frequency
-   Error reduction
-   Processing time
-   Team productivity

Examples:

-   Reduced cloud costs by 25%
-   Improved API performance by 40%
-   Increased test coverage from 50% to 85%
-   Supported 500K daily users

Quantified achievements should receive stronger evidence weight than
generic responsibilities.

------------------------------------------------------------------------

## 9. Ownership

Determine how much responsibility the candidate actually had.

### Ownership levels

  Level                Description
  -------------------- ------------------------------------------------
  Contributor          Worked as part of a team
  Independent Owner    Owned features or modules
  Project Owner        Owned complete projects
  Technical Lead       Made technical decisions and guided developers
  Architect            Designed systems and architecture
  Organization-level   Influenced multiple teams or major platforms

Distinguish between:

-   Participation
-   Implementation
-   Ownership
-   Leadership
-   Architecture

------------------------------------------------------------------------

## 10. Leadership

Analyze technical and people leadership.

Look for:

-   Team lead experience
-   Mentoring
-   Code reviews
-   Technical decision making
-   Architecture ownership
-   Sprint planning
-   Task delegation
-   Hiring/interviewing
-   Engineering standards
-   Cross-team collaboration
-   Stakeholder communication

------------------------------------------------------------------------

## 11. Career Progression

Analyze whether the candidate's career shows growth.

Examples:

``` text
Junior Developer
       ↓
Software Developer
       ↓
Senior Developer
       ↓
Tech Lead
       ↓
Engineering Manager
```

Consider:

-   Increasing responsibilities
-   Increasing technical complexity
-   Promotions
-   Leadership growth
-   Specialization
-   Movement from implementation to architecture

------------------------------------------------------------------------

## 12. Technology Recency

A technology listed on a resume may be outdated.

For each important technology determine:

-   First usage
-   Last usage
-   Total usage duration
-   Used in current role?
-   Used in recent projects?
-   Production usage?

Example:

``` text
React
Experience: 5 years
Last used: Current role
Production: Yes
Confidence: High
```

This is particularly important when matching candidates against modern
job requirements.

------------------------------------------------------------------------

## 13. Domain Experience

Analyze relevant industry/domain knowledge.

Examples:

-   Banking
-   FinTech
-   Healthcare
-   E-commerce
-   SaaS
-   Insurance
-   Telecom
-   Manufacturing
-   Logistics
-   AI/ML
-   Cybersecurity

Also identify domain-specific concepts the candidate understands.

------------------------------------------------------------------------

## 14. Education and Certifications

Extract:

-   Degree
-   University
-   Graduation year
-   Relevant specialization
-   Professional certifications
-   Certification provider
-   Certification validity, where applicable

Examples:

-   AWS Certified Solutions Architect
-   Microsoft Azure certifications
-   Google Cloud certifications
-   Kubernetes certifications
-   Java certifications

Certifications should support, not replace, practical experience.

------------------------------------------------------------------------

## 15. Job Stability

Analyze employment history:

-   Average tenure
-   Number of employers
-   Frequent job changes
-   Long-term employment
-   Career gaps
-   Contract roles
-   Promotions within the same company

Do not automatically treat frequent job changes or employment gaps as
negative. They should be considered in context.

------------------------------------------------------------------------

## 16. Skill Gaps

Compare the resume against the target job description.

Identify:

### Must-Have Skills

-   Present
-   Partially present
-   Missing
-   Evidence insufficient

### Nice-to-Have Skills

-   Present
-   Partially present
-   Missing

Example:

``` text
Requirement: Kubernetes
Resume: Docker, AWS, CI/CD
Assessment: No direct Kubernetes evidence
Status: Missing / Requires verification
```

------------------------------------------------------------------------

## 17. Job Fit

Calculate how closely the candidate matches the target role.

Suggested dimensions:

-   Technical skill match
-   Relevant experience
-   Domain experience
-   Seniority match
-   Architecture match
-   Project complexity
-   Leadership match
-   Cloud/DevOps match
-   Education/certification match

------------------------------------------------------------------------

## 18. Seniority Assessment

Do not rely only on the candidate's job title.

Compare the claimed seniority against actual responsibilities.

### Example

A candidate claiming "Senior Developer" but only describing:

-   Basic CRUD development
-   Bug fixing
-   Following existing designs

may have weaker evidence of senior-level capability.

A candidate describing:

-   System architecture
-   Technical decisions
-   Performance optimization
-   Mentoring
-   Production ownership

has stronger evidence of seniority.

------------------------------------------------------------------------

## 19. Communication and Resume Quality

Analyze the quality of the resume itself:

-   Clarity
-   Technical specificity
-   Consistency
-   Quantified achievements
-   Clear ownership
-   Relevant information
-   Logical career progression
-   Excessive buzzwords
-   Skill stuffing
-   Contradictory dates
-   Unclear responsibilities

Resume quality should be treated as a supporting signal, not a direct
measure of technical ability.

------------------------------------------------------------------------

## 20. Potential Red Flags

Identify items that should be verified during screening/interview.

Examples:

-   Skills listed without supporting experience
-   Same technology claimed across many years without project evidence
-   Contradictory employment dates
-   Inconsistent job titles
-   Unrealistically broad technology lists
-   Responsibilities that do not match claimed seniority
-   Missing project details
-   Very generic achievements
-   Unexplained career gaps
-   Frequent short-term positions
-   Technologies appearing only in the skills section

These should be treated as **verification signals**, not automatic
rejection criteria.

------------------------------------------------------------------------

# Recommended Scoring Model

A 100-point technical candidate score can be structured as:

  Category                        Weight
  ---------------------------- ---------
  Technical Skill Match               25
  Relevant Experience                 15
  Technical Depth                     15
  Project Complexity                  10
  Architecture/System Design          10
  Problem Solving & Impact            10
  Job/Seniority Fit                    5
  Domain Experience                    5
  Leadership                           3
  Education/Certifications             2
  **Total**                      **100**

The weights should be configurable based on the job role.

For example, an **Engineering Manager** role should give more weight to
leadership, while a **Backend Engineer** role should give more weight to
technical depth, architecture, APIs, databases, and scalability.

------------------------------------------------------------------------

# Important Analysis Principle

The most reliable resume analysis should distinguish between:

**Mentioned → Used → Used in Production → Owned → Designed → Led**

For example:

``` text
AWS
  ↓
Mentioned in skills
  ↓
Used in project
  ↓
Used in production
  ↓
Designed AWS infrastructure
  ↓
Owned cloud architecture
```

This distinction provides a much more accurate assessment of technical
candidates than simple keyword matching.

------------------------------------------------------------------------

# Suggested Final Candidate Summary

A useful automated summary should answer:

1.  **What is the candidate's technical profile?**
2.  **What technologies are they actually experienced with?**
3.  **How deep is their experience?**
4.  **What projects have they delivered?**
5.  **What level of ownership did they have?**
6.  **Have they demonstrated measurable impact?**
7.  **Does their experience match the target job?**
8.  **What skills are missing?**
9.  **What claims need interview verification?**
10. **What should the interviewer focus on?**
